Engineering blueprint

Build a client,
not a dependency.

Genycaster is written around C++ modules, Qt Quick and explicit ports for providers, persistence and signer operations. This guide shows the real implementation shape rather than pretending one API can replace an entire social stack.

Prerequisites and source checkout

For the application build you need a compatible C++20 compiler/toolchain with modules support, CMake and Ninja, Qt 6.12+ including Qt Quick/QML. Browser builds additionally need the matching Qt for WebAssembly toolchain and Emscripten. Check the repository's CMakePresets.json and build profiles for platform details.

Source checkout
git clone https://github.com/genyleap/genycaster.git
cd genycaster
git rev-parse HEAD

The latest source is in active beta development; a cloned checkout and an installed Qt toolchain are not proof of a passing production release on every operating system.

Build and test

Qt 6.12 development preset (matching host toolchain required)
cmake --preset ui-qt612-debug
cmake --build --preset ui-qt612-debug
Representative contract tests (configured build directory required)
ctest --test-dir build/ui-qt612-debug --output-on-failure

These commands are developer build instructions, not Balaji's proposed three-command server/node/client provisioning. They require a correctly configured platform SDK.

Implement the capability boundaries

1 Define protocol-domain types

Canonical FID, Cast, Profile, Follow link, and signed message IDs must not contain vendor-specific JSON keys. Keep provider DTO decoding at the adapter boundary.

2 Define read and write capability ports

Specify which operations each adapter actually supports, with expected failures for missing features. Raw /v1 Snapchain endpoints and an indexed /v2 social API are not interchangeable.

3 Add a registry and routing policy

Resolve each capability using provider descriptor, enabled feature, health, privacy constraints and explicit fallback consent. Preserve per-provider opaque cursors.

4 Cache normalized results

Store normalized entities and timeline references using SQLite; render cached snapshots before optional async refresh. Never block the Qt render thread on HTTP or heavy JSON work.

5 Sign locally and pin durable write affinity

Maintain a dedicated writer route, durably associate queued messages with the chosen validator, and reconcile canonical hashes before retrying uncertain submissions.

The independent stack, in production

Provision independent storage and connectivity, run and synchronize a protocol reader, implement the canonical domain plus capability adapters, authorize an account's client app key through a trusted flow, select a validator for signed writes and build client-origin filtering using verifiable provenance. Treat each as a separately testable acceptance requirement.

Do not couple correctness to a single provider.

Genycaster's recommended engineering contract is provider-neutral. Keep the UI local-state driven, route requests by capability, and persist exact write affinity.
