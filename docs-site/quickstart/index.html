How Genycaster is organized

Genycaster is a cross-platform Farcaster client built with C++ and Qt Quick. The interface uses canonical local state, while optional background reads update that state through a capability-aware provider router. A read node, an indexed service and a write validator can be different connections.

Select a node in the client

  1. Open Settings → Node management.
  2. Look at Currently reading from to identify the active reader. A green selected marker shows configuration, not guaranteed live uptime.
  3. Use Add read node and choose the correct API contract: raw Snapchain or indexed API.
  4. Enter the endpoint URL and optional provider key only if required. Test the connection, then select the provider.
  5. Refresh or restart Genycaster for the runtime route change to take effect; re-check the active reader and test results.

The browser may block private HTTP endpoints due to HTTPS, CORS or Private Network Access restrictions. Use an appropriately secured reachable endpoint rather than assuming localhost refers to a remote server.

Reader is not the publisher

Switching a read endpoint does not move existing queued writes. Signed messages are routed through an independent write-capable provider with durable route affinity. Learn more in write routing.

Offline and incomplete data

Previously fetched content can be displayed from local storage where the feature supports it. A raw Snapchain API supplies protocol primitives but not every derived product feature, such as global search, ranking or aggregated follower counts. An indexed source or previously cached snapshot may supply supplementary information.

When strict read selection is enabled, unsupported capabilities must not silently contact another provider. Optional fallback is an explicit privacy decision.
