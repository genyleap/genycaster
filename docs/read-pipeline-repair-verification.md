- **Responsibility:** local-first cast/feed reading, navigation-generation isolation, optional per-cast analytics, viewer-reaction snapshots, and virtualized presentation interest.
- **Public/application contract:** keep existing `ReadService` and provider-neutral `CastState`, `FeedState`, `ViewerReactionSnapshot` and continuation types. The additive per-type reaction-coverage vectors are protocol-neutral evidence, not provider DTOs.
- **Ownership:** feed-page handles belong to page generations; referenced-cast and viewer-reaction interests belong to the navigation surface and current account; per-cast Views retain counts across subscriber lifetimes but cease retry scheduling when unobserved. ## Browser reaction Gateway — shared admission and partial-response repair (2026-10-20)

The previous per-HTTP-request loop capped upstream fan-out at two **per client**, not two globally; simultaneous viewer requests could multiply concurrent public API reads. The shared `createBrowserReactionService` now owns a service-wide two-slot upstream pool and at most 32 waiting lookup admissions. Shared cast-hash reads are reused across concurrent viewers, and an individual viewer's six-second logical response deadline cannot abort a shared provider request required by others. Deadline expiry returns an immutable copy of verified positive results accumulated so far; absence remains unknown, never `false`. Failed or rejected lookups receive a five-second unavailable backoff; old positive evidence remains cached for its existing TTL. Response bodies are streamed with a 3-MiB limit even when content length is absent, and parsing examines at most 100 results.

## Additional source-confirmed changes (current working tree; not deployed)

- `cancelFeedRequest` no longer cancels shared preview or reaction requests. Identity changes invalidate the whole surface; pagination/same-identity refresh invalidates only page generations. Leaving the feed for a cast, profile or notification view explicitly clears the identity; returning to the same feed is not mistaken for a continuation. Referenced-preview callbacks check surface generation, continue after cached intermediate results, and accept handles only while in flight. Account identity changes clear account-scoped reaction evidence. Cancellation of the primary, page and viewer-reaction transport handles happens after releasing ownership mutexes to avoid inline completion reentrancy. Page size and reference-hydration limits are snapshotted on the GUI thread, not read from Qt objects in worker callbacks.
- Fresh cast content is persisted and delivered as the primary ready snapshot before optional author-profile acquisition. Author enrichment is separately delivered if successful; its network failure does not hide the cast or replace replies. A deterministic native C++ fixture with controllable late successful **and failed** author completions asserts prompt Ready cast/replies delivery and no failure regression. This does not yet remove the provider adapter's own base-plus-supplemental profile barrier.
- Per-cast Views admission now merges queued metadata, differentiates unsent cancellation from network failures, schedules interested retries, recovers from queue saturation, retains verified counts on failure, and has an explicit end-to-end client deadline of 8 seconds (gateway logical budget 6 seconds). It uses a single bounded follow-up after improved metadata on an unsuccessful active request. The QML call uses a single castData descriptor to avoid mixed cast identity/author/text property updates.

## Confirmed causes and changes

- Explorer continuation was reloading both shard event windows and sorting them again. A bounded in-memory cache holds up to three windows, at most 4,096 hashes per window, for 45 seconds. The deterministic provider test now expects two event requests for two slices of one window, instead of four. Both independent Snapchain shard requests are now issued concurrently and joined exactly once; a deterministic delayed-shard fixture proves overlapping admission and a malformed-shard fixture proves one terminal error. A first-page refresh with cursor offset zero bypasses the 45-second window cache, so newly confirmed casts are not hidden by an unchanged shard head; paginated continuations still reuse the cached window.
- Background quote/parent previews requested a full conversation. Prefetch now uses the lightweight single-cast path and avoids optional author fetch on the critical preview completion path.
- Cache/decode admission rejection could lose moved callback ownership, strand reads, or deadlock a fallback mutex. These paths now deliver an explicit failure without invoking a moved-from completion or re-entering the held lock.
- Viewer reaction requests could repeatedly read up to 10,000 account reactions and treat missing entries in partial provider responses as false. Fallback is limited to 256 per type, incomplete scope remains unknown, incompatible batch capabilities back off for 15 minutes, and complete target evidence is tracked per viewer for 90 seconds. Late generations cannot commit to the newer surface. The legacy WASM-only QML positive-evidence fallback now admits at most 32 queued targets and retains at most 256 recently observed targets without evicting the separate optimistic local reaction map.
- A feed-page continuation canceled unrelated preview and enrichment reads. It now cancels only the replaced feed operation. Automatic pagination uses a single cap with duplicate/no-progress detection.
- The QML feed's stable payload side store now sweeps obsolete IDs after incremental reconciliation; a 350-window JavaScript execution fixture proves old media/embed payloads are released without disturbing visible row order. Thread QML recursively instantiated reply delegates. Detail rendering now passes flattened reply rows to a recycling ListView; nested reply entities and ordered relationships persist through a compatible additive SQLite migration. Decoder and persistence independently validate node and depth bounds, returning a failure rather than silently truncating.
- Local feed continuation removed two redundant whole-timeline reads from the normal path. A new local entity-port `findCastShallow()` keeps feed materialization from walking cached conversation edges for each row, while the detail-read port still reconstructs the full offline thread. A restart-and-feed regression test validates both paths. The SQLite entity store now prepares its cast/embed write and read statements **once per conversation** instead of once per reply; a 96-reply/192-embed mixed URL and quoted-cast fixture verifies consistent round-trip ordering and payloads. An opt-in `ReadOptions::pageOnlyContinuation` now publishes only the newly persisted provider page to the Qt consumer, where `PresentationBridge::applyList` reconciles it by stable Cast ID; old readers still receive the complete accumulated snapshot. The new async regression uses a counting `IReadStore` wrapper to verify that continuation delivery performs **zero whole-feed materializations**, persists the page durably, and retains backward-compatible full snapshots for other consumers. Full first-page materialization and the broad `QVariantList` presentation surface remain performance limitations.
- View counts were fetched and parsed in QML. A Qt presentation adapter now owns HTTP and JSON, with batches of 16, up to 96 queued targets, 384 retained per-cast count objects, 3-minute valid freshness, 90-second unavailable retry and 8-second end-to-end transport deadline (distinct from transfer inactivity); unavailable views remain unknown. Previous 6-second deadline is superseded by this iteration. Derived analytics may be disabled using `FARCASTER_ENABLE_DERIVED_CAST_VIEWS`.
- The Views gateway uses one shared upper limit of three active upstream queries, 32 waiting upstream admissions and a six-second overall logical budget. Tests verify partial results and exact hash/author matching.
- Native LinkPreview and CollectiblePreview reserve thumbnail, poster, two-line title, metadata and badge space before late image/metadata; loaders and failures retain the same card geometry across scrolling. This eliminated 29 real `ui.media_scroll` failures in a diagnostic native-Qt run: web/youtube/miniapp heights at both tested widths stayed identical before/after metadata and image completion, with spinning indicators preserved during flicks.
- The native link resolver admits at most two active requests and 64 queued URLs, caches up to 320 previews, and refreshes after 15 minutes. Newer, still-relevant queued URLs displace older unstarted previews.
- Reaction presentation applies each batch in one pass, avoids replacing untouched rows, and emits no change signal for repeated or offscreen results. Local optimistic overlays retain precedence. Incremental feed pagination now tracks precisely the inserted/revised row indexes and reapplies reference, reaction and follow overlays **only to those rows**; a real Qt Presentation test with 180 existing casts verifies fresh/revised row hydration, duplicate reconciliation, and unchanged rich prefix. Full refreshes and locally authored rows retain the complete reconciliation path. Referenced-cast hydration now skips rewriting unchanged visible QVariant rows and suppresses repeated/offscreen notifications. Recursive quote/parent preview reconciliation returns an actual change flag, so a quote nested in threaded replies triggers precisely one detail refresh; real Qt unit tests check initial, duplicate and revised metadata deliveries.
- The GCC 16 composition root was split from 5,652 lines into an approximately 1,800-line GUI entrypoint and a dedicated runtime/UI signal-binding translation unit, with unrelated provider/storage module imports removed. The full native Qt executable now builds and links successfully on the 4 GiB host (Ninja [10/10], exit 0); its runtime integration test subsequently reached the local fake provider and passed.
- Idle `GenyVideoPlayer` instances no longer create `QAudioOutput` before a playback request. This prevents the Qt 6.12 Multimedia/PipeWire system-audio probe observed to crash the headless executable during QML startup, without suppressing sound for activated playback. A new JavaScript regression asserts deferred audio initialization.
- Executor worker and Qt HTTP reactor callback invocation have exception guards to avoid process/thread termination. Callbacks must still translate their own unexpected failures into domain-typed terminal results.
