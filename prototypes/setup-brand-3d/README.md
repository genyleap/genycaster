# GenyCaster · GPU Glass Design Prototype v2

**Isolated experiment:** This project does not replace or modify production
`InitialSetup.qml`, the eight Setup stages, profile data or authentication.

Live preview: https://caster.genyleap.com/preview/brand3d/index.html

## What changed from v1

The first attempt produced hard-edged, flat, low-detail forms. A significant
geometry bug then surfaced during real Chromium rendering: the second triangle
of each quad used **seven indices rather than six**, causing degenerate
triangles and a visible checkerboard/mesh artifact. The procedural generator
has been corrected, and the repository tests now reject degenerate panel
triangles to prevent recurrence.

The revised independent scene contains:
- Three smooth, genuinely curved glass shells with 3D thickness and
  independently traced luminous bevels.
- One sculptural crescent and a small physically refractive glass orb.
- Two independently generated studio environment light probes, a warm
  champagne-gold kicker and teal reflection accents.
- Pinned local Three.js 0.170.0 (MIT), with PBR material on the dark panels and
  stable GPU Fresnel thin-film shading for light panels; browser validation
  showed this split avoids unpleasant washout in the light theme.
- Real pointer-driven parallax, brief click pulse and event-driven rendering
  (no permanent animation loop).
- Readable 2D logo, copyright and version; reduced-motion toggle and system
  preference support.

## Layout and independent preview

- `index.html` — desktop two-column mockup. The right side is a design
  placeholder, not live onboarding functionality.
- `scene.js` — self-contained interactive WebGL 2 scene; imports only the
  pinned `three.module.js` stored alongside it.
- `assets/brand-dark.glb`, `brand-light.glb` — matching 11-mesh scenes
  with theme-specific material bases, generated by `generate_assets.py`.
- `assets/studio-dark.png`, `studio-light.png` — procedural studio light
  probes, generated by `generate_environment.py`.
- `Prototype.qml` — independent Qt Quick 3D native trial using the same
  models and probes. Its environment needs a real hardware Qt Quick 3D render
  check before production integration.
- `Capture.qml` and `verify_native.py` — optional Native smoke test.
- `THREE_LICENSE.txt` — the Three.js MIT license.

No remote textures, model services, external JavaScript runtime, or network
accounts are required for the preview assets.

## Tests

```sh
python3 generate_assets.py
python3 generate_environment.py
node --test ../../tests/wasm/brand_3d_prototype.test.mjs
```

We also rendered both browser themes with Chromium headless, WebGL 2 and
software SwiftShader during development; both loaded without page errors,
and screenshots were manually compared. This is an actual browser render,
not an image-generation concept.

**Important limitations:** The new browser version is materially better
than v1, but it is still an exploration and not a pixel-perfect recreation
of the concept render. Real device rendering may vary with driver/GPU.
Production GenyCaster currently does not bundle Qt Quick 3D for its Qt
6.12 WASM target, so a final cross-platform integration design remains
necessary. Do not swap the production sidebar on the strength of mockup
screenshots alone.
